# 開発・公開前検証の方針

2026-11-14の利用者指示に基づく。

- ステージングや別のホスト型検証環境は使用しない。ローカルで検証し、本番固有の条件は未確認として明記する。
- DB変更では必要に応じてローカルSupabaseの実Auth／PostgREST／PostgreSQLを使う。PGliteやHTTP代替だけで実サービス確認済みとはしない。
- 既存ローカルDBを不用意にresetせず、未リンクの使い捨てローカルプロジェクト・合成データを使える。本番の認証情報・データを流用しない。
- 成功済みのテストは変更や新しい懸念がある範囲だけ再実行する。未確認の経路、権限、境界、性能、バックアップ／復旧を優先する。
- 本番適用前に最新バックアップ、復旧権限・復旧点、許容する損失・停止時間、直前アプリ版、移行履歴を確認する。古い監査記録を現在の保証に使わない。
- 本番固有の設定差・実負荷等は、適用直前の確認と適用後の限定的な実データ確認・監視で扱う。無断で本番負荷試験やテストデータ投入をしない。
- **本番DBへのマイグレーション適用とVercelデプロイは、利用者が明示的に許可するまで実行しない。** ローカル検証の許可や条件付きの公開可判定は本番実行の許可ではない。
- 報告では確認済み・未確認・問題ありを区別し、適用可否、残存リスク、適用後の確認、停止条件、復旧手順を示す。ステージングがないことだけを公開不可の理由にしない。

推移分析の検証例は [environment-trends.md](environment-trends.md) を参照。
