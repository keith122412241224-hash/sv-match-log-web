# 将来の自動更新

初版の運用主体は管理者と既存のChatGPT契約。外部情報を調べる作業はChatGPT上で行う。アプリに定期処理や有料APIクライアントは含めていない。

## 共通にする境界

| 段階 | 利用する処理 |
|---|---|
| 実測集計 | 同一の管理者認可と集計RPC、スナップショットビルダー、保存RPCを使用する |
| 分析 | 許可された取得手段で外部情報を調査し、固定した版のプロンプト・スキーマと候補一覧を使い、対象別の有効資料・構造化理由・未掲載理由を生成する |
| 検証 | 保存済みの環境・マスタ・スナップショットで `validateEvaluation` と共通のワークフローを通す |
| 保存・公開 | `environment_review_transition` で同じ履歴・版照合・環境単位の排他制御・投影検証を使用する |
| 失敗 | 管理者専用の失敗イベントを記録する。公開行の更新は成功トランザクションの確定時のみ |

## 着手前に検証すること

1. 03:00 JST（前日18:00 UTC）にPC停止中でも動く実行主体があり、既存契約で検索・ファイル授受・必要な通知まで可能か検証する。調査手段の利用条件と費用を確認する。
2. 検証に合格した場合だけ、短命の認証、操作・環境を限定した権限、サーバー側の有効化スイッチを設計する。ブラウザのセッションやサービスロールキーの共有で代用しない。
3. 同じスナップショットIDを再試行に使う。DBの `mode` はmanual/autoを区別できる。自動実行用の限定された呼び出し元を用意し、同じ保存処理へ渡す。環境が切り替わった場合は古い実行を終了し、新しい環境の入力から始める。
4. 自動公開には、スキーマ、照合、根拠、信頼度、古さの全チェックに加え、対象環境の継続、情報不足を確認する。v2の共通ワークフローは、初回を含むデータからの二段階補正と有利不利の逆転、および前回公開からの二段階以上の変動を独立に判定し、警告が残るauto実行の公開を拒否する。自動公開を有効にするまではすべて下書きで止める。人手確認が必要な結果・処理失敗は管理者へ通知する。
5. 二重起動、取得失敗、タイムアウト、認証失効、公開直前の環境切替、閾値変更、途中からの再開を隔離環境で検証する。実運用データによる再評価の際は評価ルールの版と判断材料を残す。


旧版を再評価する場合は新しい実行を作成し、元のスナップショットと公開履歴を保持する。データ保留の対象は総合も保留とし、過去時点の外部資料を復元できない場合は外部補正を未検証として扱う。
