# 総合環境評価の分析用JSONと実測評価

管理者画面からダウンロードするJSONは、保存済みの実測スナップショット `snapshot` と、同一環境の比較用公開評価 `previousEvaluation` を持つ。初回など比較対象がないときは `null`。ChatGPTにはこのファイルを分析材料として渡し、結果は入力仕様に沿った別のJSONで返す。

## 対象範囲と時刻

集計RPC `get_environment_review_source_v2` は管理者セッションの単一SQLスナップショットで、v1の表示母集団とTier対象母集団の登録者集計を取得する。両RPCともSECURITY INVOKERで、既存の戦績・マスタの読み取りポリシーを適用する。環境は `matches.environment_id` で限定する。集計終了が設定済みで経過していれば `dashboard_end_at` の時刻、それ以外は現在時刻を30分単位で切り下げる。環境の開始は既存推移分析と同じく `start_date` の日本時間0時、未設定なら `created_at`。直近72時間と168時間の開始をそれぞれ環境開始まで繰り上げる。開始を含み、終了を含まない。環境開始が集計終了より未来なら作成を受け付けない。

v2は、環境と期間に該当する戦績からさらに `matches.created_at < asOf` を満たすものを選ぶ。期間内に対戦し、締切ちょうど・締切後に登録した戦績は、表示用勝率・遭遇率・Tier・偏り指標のすべてで次回以降の対象になる。終了を固定した環境では以後も除外される。マスタも `deck_archetypes.created_at < asOf` を満たす分類を使う。旧版v1と既存ダッシュボードは対戦時刻で集計するため、遅れて登録した戦績があれば同じ対戦期間でも件数に差が出る。締切後に編集・削除された既存戦績や改名されたマスタの当時の内容を復元する履歴はなく、作成時点で保存したスナップショットを再利用する。

| snapshotの項目 | 意味 |
|---|---|
| schemaVersion / ruleVersion / confidenceRuleVersion / promptVersion | 新規出力は `2`、`environment-review-v2`、`review-confidence-v2`、`environment-review-prompt-v2`。保存済みv1は旧版の値を維持 |
| environmentStart | 集計の7日開始より前も含む環境本来の開始時刻。外部情報の時点照合に使用 |
| snapshotId / environmentId / environmentName | 保存済みスナップショットUUID、対象環境UUID、表示名 |
| asOf / periodStart / shortPeriodStart | タイムゾーン付きISO日時。共通の集計終了、7日開始、3日開始 |
| ranks | 既存ランク選択の17区分すべて。登録者の対戦時点のランク。未登録は `unranked` |
| matchCount / shortMatchCount | 全期間、短期間の戦績登録件数。双方が同じ実戦を別々に登録した場合も既存と同じ登録単位 |
| contributors | 全期間の異なる登録者数 |
| decks / pairs | 以下のデッキ別・対面別の確定値 |

## デッキと対面

デッキは共通または当該環境のアーキタイプを対象とし、有効マスタと期間内に観測した無効マスタを含む。個人デッキIDを代用しない。未分類・環境外の分類はデッキとして出力せず、登録件数と遭遇率の分母には含める。他方が既知なら、そのデッキの実測勝率には含める。

| decks[]の項目 | 意味 |
|---|---|
| deckId / name / className / isOther | マスタUUID、名称、クラス、「その他」分類か |
| registrations / count / wins / winRate | 当該デッキを含む登録数、両者視点の評価件数、その勝数・勝率。ミラー1登録は2評価、1勝 |
| encounters / encounterRate | 相手側に出た登録数と、期間の全登録数に占める率。全登録があり遭遇が0なら0% |
| useCount / useWinRate | 使用側での登録数、その側から見た勝率 |
| eligibleCount / eligibleWinRate / interval95 | ミラー・未分類・その他を除くTier候補判定の件数・勝率・95% Wilson区間（百分率の下限・上限） |
| dataTier | 後述の数値1〜5、または保留のnull |
| contributors / pilots | 当該デッキがどちらかに登場した対戦の登録者数、自分で当該デッキを使用した登録者数 |
| topContributorShare / userEqualWinRate | 最大の1登録者が当該デッキ評価件数に占める率、各登録者の当該デッキ両者視点勝率を等重みで平均した率 |
| short / byRank / byDay | 3日間のデッキ成績、登録者ランクをキーにした7日間の成績、日本時間の日付をキーにした日別成績。各成績に registrations / count / wins / winRate / encounters / encounterRate / useCount / useWinRate を収録 |
| byTurn | first（先攻）とsecond（後攻）の各成績。count / wins / winRate。対象デッキが相手側に登場した場合は先後と勝敗を反転 |

対面は、期間内に観測した異なるマスタ同士をUUID昇順の `a`, `b` で1回だけ保持する。`count` は両方向の登録数、`wins` と `winRate` はa視点。`short` と `byRank` と `byTurn` は同じ視点のcount / wins / winRateを持つ。`interval95` はa視点の95% Wilson区間。`dataRating` は−2〜2の整数または保留のnull。逆方向の評価は符号反転で決まる。ミラーは対象外、未観測の組は保留。割合は0〜100の数値で保持し、分母0ではnull。ランク・日付キーの欠落は、その区分で全登録が0であることを示す。

各対面の `contributors` は当該組を登録した人数、`topContributorShare` は最大の1登録者が当該組の登録数に占める率、`userEqualWinRate` は登録者ごとにa視点にそろえた勝率の単純平均を表す。個人ごとの内訳はエクスポートされない。

## 旧版Aの実測ルール environment-review-v1

設計時の分布は既存のローカル検証記録 `build/environment-trends-production/rpc-all.json` の最終点で確認した。2026年11月15日19時30分時点、全ランク、7日移動集計812登録。選択24デッキの両者視点の評価件数は0〜481件、中央値39.5件。10件未満は6デッキ、20件未満は9デッキだった。これは単一環境の計測例で、現環境への精度評価ではない。以下のしきい値と標本区間は運用上の初版として固定する。

1. Tier用の母集団は既存期間レポートの `periodDeckPerspectives(..., true)` に倣い、両者視点を統合する。ミラー・未分類・「その他」相手は除く。「その他」の分類自体も保留。
2. 既存週報の最低10件に満たなければ保留。登録側・反転側が各20件以上でその勝率差が25ポイント以上の場合も、週報と同じく保留にする。この登録側の差だけで外部評価との乖離を認定しない。
3. Tier1は40件以上、勝率56%以上、95% Wilson下限が50%超。Tier2は20件以上、勝率53%以上、同じく下限が50%超。順に判定する。56/53/50%は既存週報の勝率基準、20/40件は少数での上位評価を抑える下限。
4. 次に勝率50%以上はTier3。40件以上でWilson上限が45%未満ならTier5。残りはTier4。総合TierとデータTierは別の項目として保持する。
5. 対面は10件未満と「その他」の対面を保留。実測勝率が60%超は+2、55%超〜60%は+1、45%〜55%は0、40%〜45%未満は−1、40%未満は−2。既存環境相性表と同じ境界を整数勝数で比較する。管理者は信頼区間・ランク・先後も確認して総合相性を判断する。

Wilson区間は正規分布の両側95%に相当するz=1.96を用いる。同一登録者の戦績や同一試合が含まれる可能性があり、これは標本の不確実性を確認する目安。区間や件数だけで外部評価との乖離を決定しない。次版にしきい値を変更した場合はruleVersionを更新し、過去の保存済み評価は作成時の版を維持する。

## v2の採用判断と処理順

1. 管理者用RPCが表示用・評価用の母集団を同じデータベース時点で集計する。新しい `environmentStart` と登録者集計を取得できない場合、新規スナップショットの作成は失敗する。既存の保存済み評価は元の版で参照できる。
2. `metrics.ts / buildReviewSnapshot` が従来の観測値とAを計算する。`data-model.ts / buildReviewSnapshotV2` が同じ入力からCと診断を追加する。管理者はA、C、採用結果を別々に参照できる。
3. **データTierにはAを採用する。** 将来7日勝率との時点別順位相関の平均は5環境でA 0.262、B 0.192、C 0.273だった。現在環境ではCが上回ったものの、過去4環境ではA 0.282、C 0.272で、上位Tierの将来勝率は全体で両者とも53.5%だった。環境によって結果が入れ替わり、主要対面の観測範囲も異なる。このため環境適性は比較値として提示する。`dataTier = model.legacyTier`、`model.candidateTier` にCを保存する。
4. **データ対面相性にはCを採用する。** 判断材料の乏しい勝率帯を保留にするためである。全5環境の将来7日では、Aは方向を出した336組中179組で将来勝率の方向と一致し、方向判定カバー率は29.7%。Cは57組中41組で一致し、カバー率は5.0%。この57組ではAとCの方向はすべて一致した。現在環境の留保検証ではAは89/142、Cは26/37、カバー率は38.1%と9.9%。Cは方向を確定する対象を絞る。Aに対して方向予測自体が改善したとはいえない。`dataRating = model.candidateRating`、`model.legacyRating` にAを保存する。

指標の分母・期間、時点別・環境別の比較、情報リークへの対応はバックテスト報告を参照する。データ区分、主要5対面、区間・集中・人数のしきい値を環境ごとに後付けで調整しない。

### 比較対象B（週報）

実装は `weekly-report.ts / buildTierCandidates, weightedMajorMatchupWinRateFor, calculateStrengthScore, suggestTier` と `weekly-report-config.ts`。勝率を百分率で表し `s(x)=max(0,min(100,4×(x−40)))` とする。週報の複合点は以下の和で決まる。

| 入力 | 複合点への寄与 |
| --- | --- |
| 合算勝率 R | 0.45 × s(R)。欠損時50% |
| 主要対面勝率 M | 0.35 × s(M)。各10件以上の対面をそのデッキの対面件数で加重。欠損はR、Rもなければ50% |
| 件数 | 0.15 × 100（20件以上）、65（10〜19件）、25（9件以下） |
| 前期間の勝率からの増減 Δ（ポイント） | 0.05 × clamp(50+3Δ,0,100)。週報の比較可否条件を満たさなければ50を使う |

10件未満または両視点乖離なら保留。その他は勝率が56/53/50%以上かつ複合点が78/66/54以上で順にTier1/2/3、残りはTier4。週報の上位分布における存在感は遭遇率10%以上でHigh、5%以上でMedium、残りがLowとして別に表示する。Bの利点は主要対面と前期間の推移を説明できること。注意点は、同じ勝敗が全体勝率と主要対面の両方に寄与し、戦績件数自体が強さの点数になること。週報には総合環境評価と同じ5段階の対面相性・Tier5がなく、相関図で10件以上・55%以上の方向を出す。

### Cの環境適性と比較Tier

実装は `data-model.ts / wilsonCenter, buildReviewSnapshotV2, candidateDeckTier`。`n` を評価対象件数、`w` を勝数として、評価用勝率を `S(w,n)=100×(w+1.96²/2)/(n+1.96²)` とする。これはWilson区間の中心で、小標本の値は50%に近づく。0件ならnull。実測勝率は `100w/n` で保持する。

1. 各デッキに対し、自己・「その他」・未分類を除く既知の相手を全環境内の当期間の相手側遭遇件数で降順に並べ、同件数はマスタID昇順とする。最初の5デッキが主要対面。自己デッキの遭遇率による加点はない。
2. 各相手の重み `q = その相手の遭遇件数 / 自己等を除く全相手の遭遇件数`。主要対面のうち両方向を合わせ実測が10件以上なら `used=true`。重みは観測済み対面だけで再正規化しない。
3. 全体の評価用勝率を `S₀`、利用できる主要対面の評価用勝率を `Sⱼ` として、`effectiveRate = S₀ + Σ qⱼ(Sⱼ−S₀)`。1つの環境分布に標準化した推定値で、観測不足の対面・主要5以外の重みの部分はS₀で補う。対象戦績が0件ならnull。対面間差の独立性や同一人による反復を補正した推定量ではない。
4. `coverage = 100 × Σ qⱼ` は10件以上観測できた主要対面がカバーする遭遇分布の割合。`majorMatchups` に対面別の件数・勝数、Wilson中心・区間、重み、採用可否を保存する。`fitConfidence` はカバー率0なら判断保留、50%未満なら低、その他は実測信頼度を上限とする。50%は分布の過半を観測したかを示す運用上の線である。
5. Cの比較TierはAの保留条件・対象件数・全体実測のWilson上下限を維持し、勝率56/53/50%の判定箇所だけをeffectiveRateに置き換える。全体の区間をeffectiveRate自体の信頼区間として表示しない。ランク・推移・ユーザー均等勝率を直接加点する項目はない。

### Cの対面相性

正規化したIDの小さい方a視点で計算し、b視点は符号を反転する。`candidateMatchupRating` で、10件未満、「その他」またはミラーは対象外。Wilson95%下限L、上限U、中心Sはいずれも百分率。以下を上から適用する。

| 条件 | データ相性 |
| --- | --- |
| S > 60 かつ L > 55 | +2 |
| S > 55 かつ L > 50 | +1 |
| S < 40 かつ U < 45 | −2 |
| S < 45 かつ U < 50 | −1 |
| L ≥ 45 かつ U ≤ 55 | 0（五分圏を支持） |
| その他 | null（保留） |

実測だけで0に分類されても区間が広ければ保留。`model.assessment` は10件以上でS>55またはS<45なら有利・不利の傾向、区間全体が同等帯に入れば五分圏、それ以外は判断材料不足。相性が保留で傾向だけ出るときは弱い方向として読む。例として7勝3敗なら実測70%、S=64.45%、区間39.68〜89.22%。Aは+2、Cは保留・有利傾向。500勝500敗なら実測50%、区間約46.91〜53.09%でCは0。

### 母集団と実測信頼度

`data-model.ts / eligibleFacets, common` と `get_environment_review_source_v2` が、所属環境内の既知の通常デッキ同士の非ミラーだけを抽出する。デッキ・対面ごとの `model.bias` はこの母集団と同じ集計。登録者ID・個人別の勝敗や率はJSONに出力しない。

| 項目 | 計算 |
| --- | --- |
| contributors / pilots | 異なる登録者数 / 対象を使用した異なる登録者数。対面のpilotsはaを使用した人数 |
| topContributorShare | 最大1人の登録件数 ÷ 同対象の全登録件数 ×100 |
| userEqualWinRate | 各登録者の対象視点での勝数÷件数×100を等重みにした平均 |
| withoutLargestWinRate | 登録件数最大の1人を除いた対象視点の勝率。件数タイは勝数の多い方、双方同じなら結果は同じ。残り0件はnull |
| upper.combined / upper.direct | GM登録者の戦績の両視点統合 / そのうち登録者自身が対象デッキ（対面はa）を使用した成績 |
| upper.all / other / unranked | 全ランク / 登録済みGM未満 / ランク未登録の対象視点成績 |
| short / direct / reversed | 直近72時間 / 使用側 / 反転側。いずれもTier対象母集団。先後もデッキ視点に反転して比較 |

**実測信頼度**は将来の勝率やTierの正しさを表す確率ではない。

- 10件未満は判断保留。10〜19件、登録者3人未満・人数不明、最大集中度が50%超・不明、登録者均等勝率または最大登録者除外後勝率が実測から10pt以上離れる、両視点に各20件以上あり勝率差が25pt以上のいずれかなら低。デッキでは実使用者2人未満または不明でも低。
- 他はWilson95%区間の幅が20pt以内なら高、より広ければ中。観測者・登録の独立性まで保証しない。人数・10pt差・20pt幅は品質上の注意を出すための運用閾値であり、予測精度が校正された値ではない。総合評価の信頼度・外部情報については [総合評価ルール](rules.md) を参照する。
- ランクの方向を強い根拠として出すのは、GM帯と登録済みGM未満帯が各10件以上・登録者が各2人以上で、各群の95%区間が重ならない場合。未登録ランクを比較群に含めない。登録者のランクは反転側の使用者本人のランクを表さない。GM固定倍率はない。
- 推移は重複する3日と7日を直接比較せず、直近72時間と7日内のそれ以前を比較する。双方10件以上で95%区間が重ならない場合に方向を出す。先後も同じ基準で差を検出し、全体の強さに加算しない。これらは探索的な注意点で、多重検定や登録者間相関を補正した有意性判定ではない。

### 計算例

デッキ甲のTier対象が35戦25勝、相手側遭遇分布が乙20%、丙20%、丁60%とする。甲の対面内訳は乙に30戦22勝、丙に5戦3勝、丁に0戦。全体の実測勝率71.43%、Wilson中心69.31%、区間54.94〜83.67%。Aは40件に届かずTier1条件を通らず、20件以上・下限50%超・勝率53%以上なので**データTier2**。

乙だけが対面10件を満たし、対面Wilson中心は70.68%。環境適性は `0.20×70.68 + 0.80×69.31 = 69.58%`、カバー率20%、適性信頼度は低。Cの比較Tierも2。外部資料や別の条件を示す根拠がなければ、この入力から総合Tierの上げ下げを支持できない。データTier2を維持するか、理由があれば保留にする。総合評価の取り込みでは固定した根拠・前回評価・補正ルールを別途検証する。
