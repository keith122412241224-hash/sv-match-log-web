# 総合環境評価 v2 の算出・検証規則

新しい実行は実測ルール environment-review-v2、信頼度 review-confidence-v2、入力 schemaVersion 2、プロンプト environment-review-prompt-v2 を使用する。保存した旧実行は元の評価値・入力・表示を保持する。v1スナップショットの入力はv1形式、v2はv2形式に限る。[旧版の規則](v1/rules.md)・[現行入力仕様](input.schema.json)・[分析文面](prompt.md)・[架空入力例](sample.json)

## 処理順とデータ評価

1. 同一環境・同一基準日時のスナップショットで、実測値、主要対面、登録者偏り、実測信頼度、機械シグナルを固定する。前回公開版も分析開始時に固定する。
2. デッキの主評価は現行方式を維持する。評価対象は同一環境の非ミラー・両デッキ分類済み・その他除外の使用側＋反転側。10件未満、その他、または両視点が各20件以上で勝率差25ポイント以上は保留。それ以外は順に、40件以上・Wilson下限>50%・勝率≥56%をTier1、20件以上・下限>50%・勝率≥53%をTier2、勝率≥50%をTier3、40件以上・上限<45%をTier5、それ以外をTier4とする。主要対面で標準化した候補値は管理比較に使用する。
3. 対面は件数10以上を対象に、Wilson中心 C と95%区間 [L,U] を使う（単位は%）。順に C>60 かつ L>55 を +2、C>55 かつ L>50 を +1、C<40 かつ U<45 を −2、C<45 かつ U<50 を −1、L≥45 かつ U≤55 を 0 とする。他は保留。「有利・不利傾向」には根拠が弱くデータ評価が保留の場合もある。中心は 100×(勝数+1.96²/2)/(件数+1.96²)。運用値と候補の集計方法は[実測仕様](export.md)に記載。
4. データ評価のまま全対象を走査し、候補と入力用テンプレートを生成する。外部資料・評価案の取り込み後に同じ関数で再計算する。件数・勝率・対象期間はクライアントから受け付けない。
5. 対象ごとの根拠、総合評価、乖離の掲載・未掲載、信頼度を意味検証する。公開時も再検証し、現時点の公開版との大幅変動を別途検出する。

## 外部資料の有効性

原典と参照ページの公開日時がどちらも環境開始〜基準日時（両端を含む）にあること。参照した内容版の時刻 versionAt を基準日時以下に限定し、版情報が不明な場合は取得日時で判定する。将来になって取得した内容を過去に利用可能だったと仮定しない。原典情報を一次資料と一致させ、原典公開 ≤ 転載公開 ≤ 取得、参照版は掲載以降・取得以前を検証する。環境開始が未記録のときの下限は集計開始。資料の環境IDは一致必須。

有効資料は applicability=current、reliability が高または中、method が observed または analysis を満たし、対象IDが targets に直接掲載されるもの。原典が集計期間内なら latest。原典がそれ以前でも同じ環境の現行構築を扱う guide は applicableGuide、それ以外は ineligible。古い流行記事の転載日で鮮度を更新しない。鮮度の判定は日時と人が記録した構築適合性による。ソース内容・版の真正性、著者関係、利用条件の事実確認は管理者が行う。

URLはHTTP(S)・認証情報なし。フラグメント、追跡用パラメータ、余分な末尾スラッシュを除去し、クエリ順を統一する。参照URLの重複はエラー。原典ホスト（wwwは除外）、申告系列名、一次資料同士の発信者名のいずれかが共通なら推移的につないで一系列とする。同じプラットフォームの独立した著者も一系列にまとめる保守的な近似。別ホスト・別名義で同じ元調査を使えば申告系列名の統一が必要。

同一対象の有効資料は内部の sourceIds に全件指定する。一系列内の対象別方向が全て同一なら系列の一票になる。全系列一致でその方向、異なる明確な二票以上があれば評価分裂。一系列内の矛盾が解決せず、独立した明確な異論も確立しない場合は比較不能。データ評価保留・有効資料ゼロも比較不能。全対象が比較可能なら available、一部なら partial、ゼロなら unavailable。省略対面があれば全件比較可能にならない。

## 総合評価への補正

Tierの強化を「元Tier−総合Tier」、対面の強化を「総合相性−元相性」とし、正が上方補正、負が下方補正、絶対値が補正幅。片方が保留なら段階差は算出しない。保留のデータ評価から数値への補正は禁止。総合を保留する場合は判断理由・残る不確実性を記す。

| 条件 | 必要な根拠 |
| --- | --- |
| 据え置き | 外部比較不能でも可。外部と食い違う場合は乖離自体を分析 |
| 一段階、外部と同方向 | 有効な直接資料と構造化理由。ランク戦資料＋external/build/tournamentの該当理由、または方向の合う実測シグナル＋同名の理由 |
| 一段階、外部と逆・概ね一致・分裂 | 独立二系列以上、直接のランク戦資料、補正方向に整合する実測シグナル＋同名理由 |
| 二段階 | 独立二系列以上が同方向、直接のランク戦資料、方向の合う実測シグナル＋同名理由、実測信頼度「中」以上。公開前に確認 |
| 三段階以上 | 取り込み拒否 |
| 有利と不利が逆転 | 初回も重点確認。総合相性とデータ相性の積が負 |
| 比較不能 | 据え置きまたは保留 |

実測理由コードは model.signals の同名項目に照合する。偏りや少数だけでは補正方向を立証できない。適性シグナルを主評価にすでに織り込んだ場合は同じシグナルを方向根拠に再利用できない。build は有効なguide、tournament は有効な大会資料、external は比較可能、split は外部評価分裂が必要。difficulty と other は追加説明に使用できる。プレイ難易度を実証したことにはならない。公開理由、内部の構造化理由、事実、仮説（空可）、不確実性は対象にひも付く。補正幅・方向・系列数はサーバーの計算結果を参照する。

## 乖離候補・重要度

候補は、実測シグナル、比較可能な外部の上振れ・下振れ・分裂、非ゼロの総合補正、同環境の前回から二段階以上の変動のいずれか。対象別の実測シグナルの入力と閾値は [実測仕様](export.md) および data-model.ts の common / buildReviewSnapshotV2 を参照する。外部の差があり、適格件数20以上・実測信頼度中以上・ランク戦資料ありなら確認済み。確認されるのは評価の差。原因は別に検証する。他の候補は要検証。候補がない場合は外部比較不能または該当なし。外部情報ゼロで内部の不確実性だけを掲載する場合は要検証・判断保留。外部との比較状態は別項目 externalTrend で保持する。

候補の素点は 1＋以下の該当個数。各行が最大一点。

- 重要な対象。デッキは遭遇率10%以上、対面は両デッキが各10%以上。
- 不確実性。実測シグナルが二つ以上、または concentration / smallSample がある。
- 評価差。補正がある、前回から二段階以上変動、外部の方向差・分裂のいずれか。
- 根拠の厚み。適格20件以上、外部の差・分裂あり、独立二系列以上を全て満たす。

候補は最低2・最高5。逆転は5、二段階以上の補正または前回から二段階以上の変動は最低4。非候補は1。重要度降順・同点は対象IDの辞書順で固定。重要度3以上は、掲載するか private の omissionReason に未掲載・追加調査の具体的理由が必要。元の候補も検査するため、重要対面をJSONから丸ごと除外するだけでは取り込めない。外部の方向が「概ね一致」でも、内部シグナルや補正により要検証となる場合がある。

## 信頼度

実測信頼度の出発点は適格10件。10件未満は判断保留、10〜19件、登録者が3人未満・不明、最大登録者が50%超、ユーザー均等または最大登録者除外で勝率が10ポイント以上変動、使用・反転の大きな不一致、またはデッキの使用者2人未満・不明なら低。それ以外はWilson区間幅20ポイント以下で高、超なら中。実装は環境適性の観測範囲も別に記録する。

総合評価が保留なら総合信頼度は判断保留。総合判定があるときは実測信頼度と次の上限の低い方（少なくとも低）に機械的に固定する。

- 外部比較不能・分裂、ランク戦資料なし、または二段階補正は上限「低」。
- 補正なし・独立二系列以上・集計期間内の信頼性「高」の一次ランク戦実測資料あり、かつデッキでは主要対面観測範囲50%以上を全て満たせば「高」まで。
- 他の比較可能な評価は「中」まで。実測が低なら、資料が豊富でも総合は低。

これらは根拠の充足度を分類する運用閾値で、正解確率や外部補正の予測精度を実証するものではない。

## 入力例と再現性

架空例のデッキ甲は適格80戦40勝、勝率50%、Wilson区間約39.3〜60.7%、使用・反転の保留条件を満たさないためTier3。実測信頼度「中」、遭遇率25%。同一環境の独立一系列のランク戦解説が直接「上振れ評価」を記録し、具体的な主要対面での選択肢を示す設定。総合Tier2への一段階補正は許可され、総合信頼度は中。重要度は 1＋主要対象1＋評価差1＝3、確認済み。甲対乙は40戦13勝、Wilson中心約34%、上限約48%でデータ相性−1。登録者集中で実測信頼度は低、両デッキの遭遇率10%以上、外部がさらに不利と直接評価する場合、総合−2への一段階補正は可能。要検証・重要度4・総合信頼度低。これらの時点・対象・入力は [sample.json](sample.json) とテストに固定してある。架空資料は実運用に使用しない。

同一の固定スナップショット・前回評価・構造化済み外部資料・総合案からは同じ補正検証、信頼度、候補、順位を得る。検索、資料の意味・独立性の申告、説明、許容範囲内での据え置き/補正の選択は人・ChatGPTの判断を含む。同じ自然言語資料で同じ総合評価を保証しない。新旧版を混在させず、履歴と内部資料で追跡する。
