# 総合環境評価の手動更新

## 管理者限定の試験運用

現在の「公開」は管理者向けの版を確定する操作。一般会員向けのタブ、レポートURL、APIは提供しない。将来の一般公開は明示的なリリースとし、公開用投影のSELECTポリシー、読み取りAPI、会員向け入口を一緒に切り替える。下書き、履歴、出典の管理者制限は維持する。

## 集計から公開まで

1. 管理者でログインし、「管理画面」→「運用ツール」→「総合環境評価管理」を開く。対象環境を選び「表示」を押す。
2. 「スナップショットを作成」で分析時点を固定する。同じ環境・集計基準日時ですでに作成済みなら、その同じルール版のスナップショットを再利用する。最新の登録状況を調べるときは集計基準時刻を確認する。過去の集計は履歴から開ける。
3. 「分析用JSONを出力」「専用プロンプト」「JSON Schema」をダウンロードする。検索できる既存のChatGPTで、これらを新しい会話に添付して分析する。v2には全対象の機械候補と、データ評価から開始する編集用テンプレートが入る。集計値・マスタ名は書き替えない。サンプルは形式を説明する架空データ。
4. 対応するスナップショットを開き、生成結果をファイルまたは直接貼り付けで入力する。「検証してプレビュー」を押し、対象期間、Tierの変更、対面の向き、乖離要因と信頼度を確認する。「管理者用の出典・判断根拠」で参照先、鮮度、重複、原典の利用条件を照合する。重要度3以上は掲載するか、内部に未掲載・追加調査の理由を記入する。数値は構造化表示を使い、資料と本文の意味・系列・版情報は管理者が照合する。データからの大幅補正と前回公開からの大幅変動の各警告を確認する。
5. 修正があれば「項目別に評価を修正」で対象を選び、「修正をJSONに反映」する。全項目をテキスト欄でも編集できる。再度検証する。既存の下書きを変更する場合は修正理由を入力する。
6. 「下書き保存」を押す。保存済みの下書きでもう一度プレビューを開き、「公開内容と前回からの変更を確認しました」を選ぶ。「確認した下書きを公開」を押す。公開反映はDB内で完了する。
7. ログイン会員画面の「環境」→「総合環境評価」で対象環境を選ぶ。詳細を開いて実測件数や根拠を確認する。相性表は行のデッキ視点。マスを選ぶと実測勝率と判断理由が表示される。

## 保留・障害・復元

- 評価材料が不足する対象は保留にする。比較できない対象や情報取得失敗は内部記録に残す。分析全体が失敗した場合は理由を書いて「分析失敗を記録」。公開済みの評価と最終正常更新日時は維持される。
- 最新の公開評価は環境ごとに1件。初版では基準日時から36時間を超えた評価に「更新遅延」を表示する。全デッキの総合Tierが保留なら「評価保留」、公開版が存在しない環境は「評価準備中」。会員API自体を取得できない場合は再試行できる。
- 公開版を編集して下書き保存しても、会員には直前に確認・公開した版が表示される。公開を取りやめる場合は該当する評価を選び「公開停止」。同じ環境の前後の評価を自動で代替表示することはない。
- 「実行・修正履歴」の「変更内容」で変更前後の内容を確認できる。過去の公開版にもどすときは操作理由を入力し、対象の公開イベントにある「この公開版へ復元」を選ぶ。復元時は元の評価日時・公開日時に戻る。操作した日時は別途、履歴に残る。
- 古い評価の通常保存・公開と重複した内容は拒否される。他の管理者の操作と競合した場合は、作業中のJSONを控えてから「再読み込み」し、対象の版を照合する。

## 導入手順

同じスナップショットを再分析したときは「同じスナップショットの保存済み案と比較」で、外部資料の識別値と、前の下書きから総合判定が変わった対象を確認できる。識別値は資料オブジェクト（要約、方向、版、取得時刻を含む）の並びを正規化したSHA-256。元サイトの内容の真正性は別途確認する。公開版がプレビュー後に同じ実行IDのまま差し替わった場合も、再プレビューが必要。

元のアプリはNext.js 15 / React 19 / Supabase。試験運用の入口は管理画面の運用ツール。公開版の画面も同じ管理画面から開く。初回導入時は既存のスナップショット・評価基盤と、v2の公開投影・集計RPCのマイグレーションをファイル名順に確認し、権限と会員・管理者の動作をステージングで検証してから対応するアプリをリリースする。テーブルを作っただけの環境に評価行は存在しない。サンプルを初期データとして登録しない。

- `get_environment_review_source_v1` は旧版管理者用集計。v2は get_environment_review_source_v2 で適格母集団の登録者・上位帯の偏りも取得する。戦績行や個別登録者IDを返さない。
- `environment_review_runs` は不変の集計、更新方式、公開前の分析と更新番号を保持する。`environment_review_publications` はその環境の会員向け投影だけを持つ。`environment_review_events` は管理者の変更、失敗理由、公開時点の版を記録する。
- テーブル直接更新権限を与えず、管理者JWT・既存の管理者登録を必須とするRPCに書き込みを集約する。試験運用中は公開行にも管理者限定のSELECTポリシーを適用し、一般会員による全3表の読み取りを制限する。APIもユーザー・管理者を確認する。管理者への付与・剥奪は既存の運用に従う。
- 正式導入前に、既存環境の `start_date` と能力変更単位の環境IDを確認する。集計は同じ環境IDの中にある未知の能力変更日を推定しない。履歴を保管する環境は削除前に保存方針を確認する。親環境を削除した場合は対応する評価履歴も削除される。
- 初回リリースの取り消しはナビ・アプリ変更を元に戻し、公開を停止する。評価テーブルの削除は履歴も失うため、保持・バックアップの判断を別途行う。


旧実行には旧版プロンプト・JSON Schema・入力例を使用する。新旧の評価は同一環境であっても別のルール版として表示・保存する。採用した主評価はデッキが従来式、対面が不確実性を反映するWilson方式。保留の対面は評価が確定するまで総合相性も保留となる。
