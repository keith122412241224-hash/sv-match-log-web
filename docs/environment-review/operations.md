# 総合環境評価の手動更新

## v3のTier評価を更新する場合

新規の分析にはエクスポートのv3Templateを使い、tierRuleを保持する。プレビューでは「管理者用の出典・判断根拠」から全デッキの基礎Tier、旧方式、新実測補正、外部込み、集計時の前回公開版を確認する。直接資料による補正や大幅変動の警告は対象と理由を読んで確認する。保存済み旧v3は元の版で開く。評価を更新する場合だけ新規テンプレートに研究記録を移して再検証し、修正理由を記入する。

## 管理者版と会員版

「確認して公開」は管理者版を確定する操作。会員は「環境データ → 総合環境評価」で、選択した環境で承認済みの会員版を読む。試験版の自動移行はない。未公開・停止中の環境は「評価準備中」。管理者の環境タブには引き続き管理者版が表示される。

### 伊藤さんが初版を公開する手順

1. 管理画面 → 運用ツール → 総合環境評価管理で、11/26能力調整後の環境を選び「表示」。集計対象・基準日時・評価内容を検証し、管理者限定で確定する。
2. 「確定版の確認・会員公開」を開き、レポートと対象環境・版ID・集計日時・確定日時を確認する。「この確定版を会員に公開」を押し、確認ダイアログで対象と版を再確認して承認する。会員版のTier変動は、承認時に同じ環境で公開中の会員版との比較。初版や停止後の再公開には比較対象がない。
3. 「この版は会員公開済み」を確認する。一般会員セッションで同じ環境のTier表・相性表を確認する。
4. 停止するには同じ画面の「会員公開を停止」で表示中の会員版を確認し承認する。管理者版の確定・停止・下書き・履歴復元は会員版に影響しない。通信失敗・競合時は再読み込みして状態を確認する。

## 集計から公開まで

1. 管理者でログインし、「管理画面」→「運用ツール」→「総合環境評価管理」を開く。対象環境を選び「表示」を押す。
2. 「スナップショットを作成」で分析時点を固定する。同じ環境・集計基準日時ですでに作成済みなら、その同じルール版のスナップショットを再利用する。最新の登録状況を調べるときは集計基準時刻を確認する。過去の集計は履歴から開ける。
3. 「分析用JSONを出力」「専用プロンプト」「JSON Schema」をダウンロードする。添付前に少数投稿・珍しい組み合わせで個人が分かる集計、前回評価の自由記述・出典URL・検索記録を確認する。メール、会員ID、Googleプロフィール、個票・メモ、認証情報や個人と結び付く内容が含まれる資料は送らない。該当時はその資料の利用を保留する。確認済みの集計と公開資料だけを既存のChatGPTの新しい会話で分析する。集計値・マスタ名は書き替えない。サンプルは架空データ。運営者は2026年11月28日に利用中のChatGPTで「モデル改善に協力する」がオフであることを確認した。これは会話や添付ファイルの削除設定ではない。適用される保存期間と過去の学習利用は未確認。利用先・設定が変わるときは再確認する。
4. 対応するスナップショットを開き、生成結果をファイルまたは直接貼り付けで入力する。「検証してプレビュー」を押し、対象期間、Tierの変更、対面の向き、乖離要因と信頼度を確認する。「管理者用の出典・判断根拠」で参照先、鮮度、重複、原典の利用条件を照合する。重要度3以上は掲載するか、内部に未掲載・追加調査の理由を記入する。数値は構造化表示を使い、資料と本文の意味・系列・版情報は管理者が照合する。データからの大幅補正と前回公開からの大幅変動の各警告を確認する。
5. 修正があれば「項目別に評価を修正」で対象を選び、「修正をJSONに反映」する。全項目をテキスト欄でも編集できる。再度検証する。既存の下書きを変更する場合は修正理由を入力する。
6. プレビューと警告を確認し、「公開内容と前回からの変更を確認しました」にチェックして「確認して公開」を押す。変更内容は必要な場合だけ下書き保存し、更新番号・公開版を照合して公開する。「下書き保存」は中断したいときに使う。保存後は自動で再検証される。競合・応答不明のときは「最新の状態を再読み込み」で入力中の案と保存内容を照合してから再確認する。
7. 完了表示の「総合環境評価を見る」で公開した環境の評価タブへ移動できる。管理者として「環境」→「総合環境評価」で対象環境を選ぶ。公開版がない環境は「評価準備中」と表示される。公開後は詳細を開いて実測件数や根拠を確認する。相性表は行のデッキ視点。マスを選ぶと実測勝率と判断理由が表示される。

## 保留・障害・復元

- 評価材料が不足する対象は保留にする。比較できない対象や情報取得失敗は内部記録に残す。分析全体が失敗した場合は理由を書いて「分析失敗を記録」。公開済みの評価と最終正常更新日時は維持される。
- 最新の公開評価は環境ごとに1件。初版では基準日時から36時間を超えた評価に「更新遅延」を表示する。全デッキの総合Tierが保留なら「評価保留」、公開版が存在しない環境は「評価準備中」。会員API自体を取得できない場合は再試行できる。
- 公開版を編集して下書き保存しても、会員には直前に確認・公開した版が表示される。管理者版を取りやめる場合は該当する評価を選び「公開停止」。同じ環境の前後の評価を自動で代替表示することはない。
- 「実行・修正履歴」の「変更内容」で変更前後の内容を確認できる。過去の公開版にもどすときは操作理由を入力し、対象の公開イベントにある「この公開版へ復元」を選ぶ。復元時は元の評価日時・公開日時に戻る。操作した日時は別途、履歴に残る。
- 古い評価の通常保存・公開と重複した内容は拒否される。他の管理者の操作と競合した場合は、作業中のJSONを控えてから「再読み込み」し、対象の版を照合する。

## 導入手順

会員公開機能はバックアップを確認し、DBの 20261126015443_environment_review_member_release.sql → アプリ → 会員の「評価準備中」と試験版の非開示を確認 → 本人が対象環境の初版を承認、の順で反映する。アプリを戻す場合も先に対象環境ごとに会員公開を停止する。DBの読み取りにも停止が反映される。履歴とマイグレーションは保持する。

同じスナップショットを再分析したときは「同じスナップショットの保存済み案と比較」で、外部資料の識別値と、前の下書きから総合判定が変わった対象を確認できる。識別値は資料オブジェクト（要約、方向、版、取得時刻を含む）の並びを正規化したSHA-256。元サイトの内容の真正性は別途確認する。公開版がプレビュー後に同じ実行IDのまま差し替わった場合も、再プレビューが必要。

元のアプリはNext.js 15 / React 19 / Supabase。評価の編集には管理画面の運用ツールを使う。管理者は環境画面の「総合環境評価」タブと管理画面の「確定版の確認・会員公開」のどちらからも同じ公開版を確認できる。初回導入時は既存のスナップショット・評価基盤と、v2の公開投影・集計RPCのマイグレーションをファイル名順に確認し、権限と会員・管理者の動作をステージングで検証してから対応するアプリをリリースする。テーブルを作っただけの環境に評価行は存在しない。サンプルを初期データとして登録しない。

- `get_environment_review_source_v1` は旧版管理者用集計。v2は get_environment_review_source_v2 で適格母集団の登録者・上位帯の偏りも取得する。戦績行や個別登録者IDを返さない。
- `environment_review_runs` は不変の集計、更新方式、公開前の分析と更新番号を保持する。`environment_review_publications` はその環境の管理者確定版を持つ。`environment_review_events` は管理者の変更、失敗理由、公開時点の版を記録する。
- テーブル直接更新権限を与えず、管理者JWT・既存の管理者登録を必須とするRPCに書き込みを集約する。管理者版・スナップショット・履歴のSELECTは管理者のみ。会員版専用表はログイン済み非匿名会員に公開中の行だけを返す。DB側で表示に必要な項目を抽出し、会員公開・停止を管理者履歴に記録する。管理者への付与・剥奪は既存の運用に従う。
- 正式導入前に、既存環境の `start_date` と能力変更単位の環境IDを確認する。集計は同じ環境IDの中にある未知の能力変更日を推定しない。履歴を保管する環境は削除前に保存方針を確認する。親環境を削除した場合は対応する評価履歴も削除される。
- 初回リリースを取り消す場合も、会員公開の停止後にアプリを戻す。評価テーブルの削除は履歴も失うため、保持・バックアップの判断を別途行う。


旧実行には旧版プロンプト・JSON Schema・入力例を使用する。新旧の評価は同一環境であっても別のルール版として表示・保存する。採用した主評価はデッキが従来式、対面が不確実性を反映するWilson方式。保留の対面は評価が確定するまで総合相性も保留となる。
